Model agent orchestration as explicit state machines (idea via Micah's dad; see slagyr/statemachine — transition tables, Mealy actions, superstates). Today's orchestration is an implicit FSM smeared across skills, band config, cron, and humans; its failures this week were lost-event bugs (orphaned claim = state with no action fired; silent turn death = state no transition exits; continuation-budget hold = manual timeout). DESIGN: (1) Per-orchestration TRANSITION TABLE, actions are prompts (Mealy); superstates for shared transitions (e.g. any-state budget-timeout -> held/notify-human). New project = one table + crew/worksite bindings, replacing the file/crew/session frenzy. (2) Two machine archetypes: per-entity instances (one per bean) for singular steps; SINGLETON ACCUMULATOR machines for collected steps (hardening): collect action appends to basket, guarded drain transition (count >= N / quiescence via cron tick / explicit), action = ONE prompt carrying the basket. (3) STATE-STORE PORT: instances = entity-id -> state + context. Beans are the default adapter (git-backed, auditable, human-EDITABLE — a human flipping status is a manual transition; re-hail is event injection); file/EDN adapter for orchestrations without repos; in-memory for ephemeral fan-outs. Usable entirely without beans. (4) EVENTS, two kinds, no new messaging scheme: SEMANTIC DECLARATIONS via a crew-side `signal` tool (signal :landed {:bean .. :commit ..}) writing event records the foreman consumes — replaces remembered hail choreography with one structured tool call, routing owned by config; INFRASTRUCTURE OBSERVATIONS emitted by the system (turn ended/died via isaac-e04k, worksite freed, commit observed) serving as BACKSTOP transitions: 'turn ended in :claimed with no signal' is itself an event the table handles (nudge/re-dispatch/escalate). The model indicates when it finishes; the machine notices when it doesn't. (5) ACTIONS ride hail unchanged (durable, deferred, attention). Composition: foreman decides WHAT, dispatch-gate/worksite module decides WHERE, hail carries, cron ticks, hooks route. New module — NOT hail (hail stays pure messaging; three-time ruling this week). Name note: 'isaac-foreman' was hallucinated into scrapper's gists by grok-4.20 two days before this design existed — confabulation as prophecy. STATUS: ponder pile with the worksite module (isaac-51xy decisions 36-39); no build until Micah rules.


## Addendum (2026-08-22, Micah): external event triggering

Events must be triggerable externally -> CORRECTED (2026-08-22, Micah's catch): hooks' essence is webhook -> prompt -> TURN; foreman events are non-turn, so reusing hooks would change what hooks is. Instead the foreman contributes its OWN route through the isaac-server route berth (the same extension point hooks and cli-server use — server owns HTTP): `POST /foreman/events` behind the server's existing token auth. Hooks unchanged, remains the webhook-means-wake-a-crew module (pinky telemetry untouched). Migration example: a CI webhook targets the event route and the TABLE decides whether any prompt fires. **Two doors, one intake**: the crew-side `signal` tool and the external endpoint write the same event envelope to the same durable queue. Durability rule (hails-never-die for events): persist-before-ack — append to disk, then 200; the machine consumes from disk, so an accepted event fires even across restarts. Unlocked table inputs: GitHub Actions posting :ci-passed (CI as first-class transition, not a report a crew reads), human curl for manual events, remote cron ticks, cross-host isaac signaling.


## Addendum (2026-08-22, Micah): observability + CLI

The machine's state IS the answer to "where is this bean?" — currently answered by digging logs/transcripts (the planner spent this week doing exactly that: ssh + jsonl tails + hail-dir greps for every status question; qxvl's stall took forensic reconstruction). Surface:
- **Read endpoints** beside the event route: GET /foreman/instances/<id> -> {state, since, last-event, pending-action, accumulator basket}; GET /foreman/instances?state=held ("what needs a human" as a query). The persisted event intake doubles as an append-only TRANSITION LOG per instance — audit trail/"how it got here" for free.
- **CLI**: `isaac foreman status <id>`, `isaac foreman list --state held`, `isaac foreman history <id>` — rides the endpoints, so it works remotely via cli-proxy (no ssh archaeology).
- **`isaac foreman signal <id> <event>`** — the HUMAN door for manual event injection (today: edit bean status + re-hail by hand), first-class and logged like any event. Three doors, one intake: crew tool, external endpoint, CLI.

## Addendum (2026-08-22): foreman x worksite composition

Two narrow seams, no shared internals: (1) actions -> dispatch gate — foreman targets a POOL logically; the worksite gate allocates a free member + takes the lock at dispatch; foreman never learns which checkout served. (2) events <- intake — worksite-freed / :pool-exhausted are infrastructure events; simple tables ignore them (hail deferral retries), richer tables model contention (:waiting-for-capacity transitions on worksite-freed). AFFINITY: pool allocation assumes worksite-stateless turns, guaranteed by land-before-handoff (signal :landed carries the commit sha — the discipline is part of the machine). Rare same-directory-across-turns needs: instance context carries a worksite PIN riding action params; the gate honors the pin instead of allocating; hail stays an opaque carrier. CORRECTED (Micah): pools are a DISPATCH-GATE feature — every turn source is a client, and HAIL is the first: band config binds crew + pool reference instead of a specific bound-session (today's work-1/work-2 bands are the manual pool this replaces); delivery dispatches to any free member, :pool-exhausted flows into existing deferral. Plain bean dispatch gets real same-band concurrency with no foreman. The foreman is one more client that generates additional concurrent work; worksites make all of it safe.

**Dependency ruling (2026-08-22):** hail and worksite depend on CORE, never on each other — worksite plugs the dispatch-gate berth (source-agnostic); hail carries opaque pool references and consumes refusal reasons as data (:pool-exhausted joins :session-in-flight in the existing deferral path). Soft coupling handled by schema berths: worksite contributes the pool-reference config schema, so a pool-referencing band without worksite installed fails config validation loudly at load.


## F1 design session (2026-08-23, Micah) — repo born: slagyr/isaac-foreman (scaffold 4cdb1c9)

- **Table format**: config entities (root :machines + config/machines/<name>.edn, both forms). SM terminology: {:start :event :end :action} rows + :initial; :* = from-any-state. Optional :states map for :entry/:exit action declarations (Mealy transitions + Moore entry/exit hybrid, per slagyr/statemachine lineage); :parent superstates + history = F6, schema leaves room.
- **Actions, three tiers**: built-in TYPES (:hail :notify :log) interpreting data; NAMED actions composed in config (machine-local :actions map; shared pool at :foreman {:actions}, machine wins) — new orchestration = pure config, zero code; berth :isaac.foreman/action only for new types.
- **F1 is record-only** (Micah): transitions append pending-action records; only :log executes. :hail execution = F3 (with delivery-failure handling), never a shelled-out side effect mid-transition.
- **Store**: default = EDN files under root — foreman/<machine>/<instance>.edn {:state :context :pending-actions} + per-instance events.ednl (transition history AND persist-before-ack intake are one append-only file). Store protocol + :isaac.foreman/store berth.
- **BEANS ARE A VIEW, NOT A STORE (Micah's ruling)**: the file store is always the local truth; beans stay fresh via an OBSERVER (declared once per machine — :observers [:beans-sync] — sees every transition; actions would be per-row forgettable choreography). Human bean-edits enter as EVENTS (:bean-edited) through the intake, not store reads. F5's beans module = observer + event source, no store impl; T2's state-map becomes that observer's config. F1 ships the observer SEAM (protocol, :observers key, built-in :log observer).
- **Name stays isaac-foreman** (orchestrator role, not mechanism; the foreman RUNS machines — config/machines/ coherent). Pure engine isolated in isaac.foreman.machine for a possible future standalone statemachine-clj extraction.
- **Unhandled events**: recorded in history + warned, never fatal (:* rows are the opt-in catch) — orchestration robustness over SM strictness.
- Roadmap: F1 engine+file store+CLI (start/signal/status/list); F2 signal tool + infra events (via isaac-bbov finalization); F3 action execution + POST /foreman/events route (+ --dry-run preserving record-only simulation — machine-testing obligation); F4 observability queries; F5 beans observer module; F6 superstates+history.

## Architecture session (2026-08-24, Micah) — turns, turnstiles, observers, addressing

- **No arrows between hail and foreman, in either direction.** Both plug into isaac-agent contracts only.
- isaac-agent already owns the turn interface (bridge.core -> drive.turn/run-turn!; CLI, comms, cron, hail delivery are all in-process callers) and every addressing primitive (sessions, crews, session tags, ensure-session!). Hail's unique value: bands-as-config (naming), thread/records, deferral's human semantics, comm reach. Selection ("pick one candidate whose turnstiles pass") moves to agent's queue — the same algorithm as worksite pools.
- **Two abstractions** (Micah): worksite wants a TURNSTILE (admission, one-at-a-time — a turnstile admits turns; name chosen for the pun); foreman wants a TURN-OBSERVER (witness of every turn's end, fired from guaranteed finalization). Turnstiles are submitted by clients (null = run-now; policy belongs to actors); observers are registered (foreman must see all turns). Invariants (session single-writer, provider walls) are core, never turnstiles.
- **Opt-in without dependency**: turnstile impls register BY NAME in agent's registry via manifest contribution; submitters reference keywords as data (:turnstiles [:worksite]). Registration is not activation. Unknown names refuse loudly + config validate checks referentially.
- **F3 SUPERSEDED**: actions do not ride hail. Foreman's native action is :turn — submit to agent's turn-request queue with its own turnstile stack; foreman's pending-actions ARE its durable queue; bbov observers report outcomes. :hail action type arrives via foreman's action berth FROM the hail module, used only when addressing/human-reach is the point.
- **Turn-request queue bean** (next session): waiting room in front of the turnstiles — submit (charge + turnstile stack + address spec {:session|:crew|:tags :reach}), hold on :hold, wake on release tokens, resolve candidates in core, loud refusal on :refuse. Hail contracts toward naming+records over this queue.
- F2's events ride the turn-observer interface (the one-sentence-turn stall of 2026-08-24 becomes a routable event: :turn-ended-without-signal -> rehail).
